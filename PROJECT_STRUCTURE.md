# Project Structure

This repository contains an Inventory Intelligence Web Portal split into a frontend application, a backend API, and shared Docker infrastructure.

## Root

```text
CEOReport/
├── Requirements.md
├── PROJECT_STRUCTURE.md
├── docker-compose.yml
├── frontend/
└── backend/
```

### Key root files

- `Requirements.md` describes the product requirements for the executive inventory intelligence portal.
- `docker-compose.yml` starts the full development stack:
  - `frontend` on host port `3000`
  - `backend` on host port `4000`
  - Prisma Studio on host port `5555`
  - PostgreSQL on host port `5432`
- `PROJECT_STRUCTURE.md` is this file.

## Frontend

```text
frontend/
├── package.json
├── Dockerfile
├── next.config.ts
├── tsconfig.json
├── eslint.config.mjs
├── public/
└── src/
    └── app/
        ├── layout.tsx
        ├── page.tsx
        ├── globals.css
        └── page.module.css
```

The frontend is a Next.js application using React and TypeScript.

### Important frontend files

- `frontend/src/app/layout.tsx` defines the root HTML layout and page metadata.
- `frontend/src/app/page.tsx` is the current home page entry point.
- `frontend/src/app/globals.css` contains global styles.
- `frontend/src/app/page.module.css` contains styles scoped to the home page.
- `frontend/public/` stores static assets served by Next.js.
- `frontend/package.json` defines frontend scripts and dependencies.

### Frontend scripts

From `frontend/`:

```bash
npm run dev
npm run build
npm run start
npm run lint
```

## Backend

```text
backend/
├── package.json
├── Dockerfile
├── docker-compose.yml
├── nest-cli.json
├── tsconfig.json
├── tsconfig.build.json
├── eslint.config.mjs
├── prisma.config.ts
├── prisma/
│   ├── seed.ts
│   └── schema/
│       ├── schema.prisma
│       └── test.prisma
├── src/
│   ├── main.ts
│   ├── app.module.ts
│   ├── app.controller.ts
│   ├── app.service.ts
│   ├── logger/
│   │   └── logger.middleware.ts
│   └── prisma/
│       ├── prisma.module.ts
│       ├── prisma.service.ts
│       └── prisma.service.spec.ts
└── test/
    ├── app.e2e-spec.ts
    └── jest-e2e.json
```

The backend is a NestJS API using TypeScript, Prisma, and PostgreSQL.

### Important backend files

- `backend/src/main.ts` bootstraps the Nest application.
  - Sets the global API prefix to `/api`.
  - Enables CORS using `FRONTEND_URL`.
  - Enables global validation pipes.
  - Exposes Swagger documentation at `/swagger`.
- `backend/src/app.module.ts` registers the main app module, Prisma module, controller, service, and request logger middleware.
- `backend/src/app.controller.ts` and `backend/src/app.service.ts` are the current base API controller/service.
- `backend/src/logger/logger.middleware.ts` logs incoming requests with colored HTTP methods.
- `backend/src/prisma/prisma.module.ts` provides Prisma integration to the Nest app.
- `backend/src/prisma/prisma.service.ts` creates the Prisma client using the PostgreSQL adapter and `TEMPLATE_DB_URL`.
- `backend/prisma/schema/schema.prisma` is the main Prisma schema. It currently defines the client generator and PostgreSQL datasource; domain models still need to be added.
- `backend/prisma/seed.ts` is the database seed entry point.
- `backend/test/` contains end-to-end test setup.

### Backend scripts

From `backend/`:

```bash
npm run start:dev
npm run build
npm run start:prod
npm run test
npm run test:e2e
npm run lint
npm run db:push
npm run db:seed
npm run studio
```

The `start:all` script resets generated Prisma client output, pushes the database schema, seeds the database, starts Prisma Studio, and starts the Nest development server.

## Generated and Build Output

These directories are generated by tools and should not be treated as source code:

- `frontend/.next/` - Next.js build and dev output.
- `backend/dist/` - compiled NestJS output.
- `backend/src/generated/` - generated Prisma client output.
- `node_modules/` directories - installed dependencies.

## Runtime Layout

In the Docker development environment:

```text
Browser
  -> frontend container: http://localhost:3000
  -> backend API:       http://localhost:4000/api
  -> Swagger docs:      http://localhost:4000/swagger
  -> Prisma Studio:     http://localhost:5555
  -> PostgreSQL:        localhost:5432
```

The intended data flow from the requirements is:

```text
SAP / Carflow / External APIs
        -> Backend Integration Layer
        -> PostgreSQL Reporting Database
        -> Next.js Inventory Intelligence Portal
        -> Optional exports and messaging integrations
```

## Suggested Future Organization

As the project grows, keep the code organized by feature and ownership:

- Frontend dashboard views should live under `frontend/src/app/` using route folders.
- Shared frontend UI components can be added under `frontend/src/components/`.
- Backend business features can be added as Nest modules under `backend/src/<feature-name>/`.
- Database models should be added to `backend/prisma/schema/schema.prisma`.
- Data ingestion jobs for SAP, Carflow, and external APIs can be added as backend modules or scheduled services.
